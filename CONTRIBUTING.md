# Contributing

Issues and pull requests are welcome. For anything larger than a small fix, open an issue first
so we can agree on the approach before you write code.

## Development setup

Requires Python 3.11+ and [uv](https://docs.astral.sh/uv/).

```bash
make install     # uv sync --all-extras
make check       # ruff lint + format check, mypy (strict), pytest with coverage
make demo        # end-to-end run on the bundled synthetic sample
make site        # build the docs site into site/
```

CI runs the same commands on Python 3.11 and 3.12. A pull request should pass `make check` and
`make site` locally.

## Ground rules

- **No network in tests.** Tests use the bundled synthetic sample or data generated in the test
  with a fixed seed. The UCI download is only exercised by `make train-uci`.
- **Numbers in docs come from runs.** `docs/MODEL_CARD.md`, `docs/img/` and
  `docs/results/uci_metrics.json` are generated by `make train-uci`; do not edit them by hand. If
  a change moves a metric, regenerate them and update any figure quoted in `README.md` or
  `docs/PRODUCT.md` in the same pull request.
- **Protected attributes stay out of the features.** `sex`, `age`, `education` and `marriage` are
  used only by the fairness audit. `tests/test_pipeline.py` checks that scores do not change when
  they do.
- **Label synthetic data as synthetic** in file names, docstrings and any output that reports it.
- Keep functions typed (`mypy --strict` runs on `src/` and `app/`) and add a test with every
  behaviour change.

## Commit messages

Imperative and specific: "Add PSI check to evaluate --data", not "updates".

## Reporting security issues

See [SECURITY.md](SECURITY.md); please do not open a public issue for a vulnerability.
